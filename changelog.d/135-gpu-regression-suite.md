### Added
- An image regression suite for the 3D renderer (`regression_render_test`): one controlled offscreen scene each for opaque models, transparency ordering, alpha cutouts and their shadows, sun shadows, skinned meshes, motion vectors, reflections, ambient occlusion, global illumination, tonemapping, grading, bloom, post antialiasing and the output formats. Each asserts what must hold on any GPU with a negative control, then compares the frame with a reference image within a tolerance.
- Behavioural regression sequences (`regression_sequence_render_test`): camera cuts by rotation and teleports drop the temporal history like an explicit reset, every size in a resize sequence draws what a fresh renderer draws, forced `baseline` and `webgl2` devices draw the plain scenes like the desktop device and fall back for the effects they lack, and a hot-reloaded shader changes the picture and its cached shadow while a failed reload keeps the last good one.
- A book chapter, "GPU regression tests": running the suites, skips and `PONKO_REQUIRE_GPU`, GPU tiers, reference images, and what each kind of failure means on other hardware.
- `PONKO_RENDER_TEST_IMAGES=1` keeps every image a regression test read back, in `target/render-test-output/`.
- `scripts/check-reference-images.py` checks the reference images against their metadata and gathers before and after images of the ones a change touches; CI's new "Reference images" job runs it on every pull request.

### Changed
- Updating a reference image (`PONKO_UPDATE_REFERENCES=1`) now needs `PONKO_REFERENCE_REASON`, leaves references that still match alone, and saves before, after and difference images. The metadata records the reason and the PNG's checksum; a reference swapped by hand, or a changed scene description or tolerance, fails the test.
- A pull request that adds, changes or removes a reference image is held by the "Reference images" job until a maintainer has looked at the uploaded before and after images and added the `references-reviewed` label.
- Every offscreen render suite opens its device through the shared test helpers, so each logs the adapter it ran on, skips with a reason, fails without a GPU under `PONKO_REQUIRE_GPU=1` and runs on a forced `PONKO_GPU_TIER`. CI's Windows unit shards now require the GPU, and every test lane uploads the images of a failed comparison.
- Reference image comparisons allow an edge to sit a pixel apart (`edge` in the tolerance) instead of budgeting for edge pixels by count, with a much smaller budget beyond that; each reference has negative controls that must fail it, and every comparison logs its measured difference (`target/render-test-output/comparisons.log`, printed by CI).
- The `references-reviewed` label covers only the images it was given for: a push that changes the references again takes it off, and the full CI run started by the `full-ci` label asks for it too.
