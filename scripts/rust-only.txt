# Rust APIs that have no C or C++ equivalent yet. Each entry is also a row of
# the "Still Rust-only" table in book/src/c-cpp.md and its chapter says so.
# scripts/check-ffi-coverage.py fails when
#   - an entry is missing from the table, or the table names something not here,
#   - the table row does not link the entry's chapter, or the chapter never
#     mentions the name,
#   - the name no longer exists in the Rust source (remove the entry),
#   - a C function of that name exists in include/ponko.h now (bind it in C++
#     too, then remove the entry and its table row),
#   - an entry has no reason or appears twice.
# The check for a C function of the same name looks only at names of two or
# more words (`scene_asset_field`, `LodHysteresis`); `font` or `get` would
# match unrelated functions.
#
# Format: <Rust name>  <chapter>  # what C and C++ do instead

Assets::scene_asset_field        asset-sources.md  # load what the scene names before load_scene
Query::with_lookup               ecs.md            # component pointers from get, which don't borrow
World::get_many_mut              ecs.md            # same
ActionMap::get                   actions.md        # copy the whole map, or read it as JSON
ActionMap::iter                  actions.md        # same
Input::set_action                actions.md        # rebuild the map and install it
systems::step_physics_access     systems.md        # no call returns a built-in step's declaration
systems::step_physics3d_access   systems.md        # same
systems::interpolate_physics3d_access  systems.md  # same
systems::step_navmesh3d_access   systems.md        # same
SystemView                       system-access.md  # C and C++ systems take the whole ctx and declare access by name
LodHysteresis                    3d.md             # no hysteresis on a LodGroup from native code
LodGroup::instance_levels        3d.md             # native code makes the batch's levels by hand
RenderPasses::scene_compute      3d.md             # native code has compute passes, effects and target cameras
RenderPasses::target_effects     3d.md             # same
AudioRolloff::Keyed              audio.md          # linear or logarithmic rolloff only
Ctx::ecs_diagnostics             agents.md         # ponko_game_schedule_plan, ponko_game_access_report, the control method
Storage::world_slots             storage.md        # bytes through storage_write and storage_read

Storage::is_persistent           storage.md        # same

UiImmediate::font                camera-ui.md      # the theme sets it
